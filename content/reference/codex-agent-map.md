# Codex 与 Agent 能力地图

## 一个可靠 Agent 怎样工作

```text
用户目标
  ↓
观察 Observe：读取文件、配置、页面和当前状态
  ↓
规划 Plan：确定步骤、风险、权限、检查点
  ↓
行动 Act：调用命令、文件、浏览器、MCP 或其他工具
  ↓
验证 Verify：测试、渲染、抽查、引用、对比不变量
  ↓
修正 Reflect：根据证据调整；达到停止条件后交付
```

模型负责理解、选择和生成；工具负责接触外部状态；环境返回真实结果；验证负责防止“流畅但错误”。

## 应该把要求放在哪里

| 表面 | 最适合 | 不适合 | 本实验室例子 |
|---|---|---|---|
| 当前提示 | 一次性目标和临时限制 | 跨任务永久规则 | “今天只分析第 1 周 PDF” |
| 当前线程 | 需要连续上下文的多轮任务 | 团队长期约定 | 30 天学习过程中的追问与纠偏 |
| `AGENTS.md` | 每次进入项目都应遵守的规则 | 单次任务细节 | 保护根目录 PDF、中文初学者表达 |
| `config.toml` | 模型、推理、权限、MCP、Agent 等客户端设置 | 业务 SOP | 默认只读或子智能体并发限制 |
| Skill | 可重复流程、领域方法、脚本和参考资料 | 简单一次性问答 | 学习资料分析 |
| 插件 | 可安装和分发的一组 Skills、MCP、Hooks 等 | 仅当前项目的小规则 | 团队共享完整外贸工具包 |
| MCP / 连接器 | 工作区之外的数据与操作 | 本地文件已有的信息 | Figma、Linear、Google Drive |
| 子智能体 | 可独立、专业或并行的子问题 | 强共享状态、一步小事 | 一个提取结构，一个审查测验 |
| 独立任务 / worktree | 需要用户单独跟进或隔离 Git 状态的工作 | 必须实时共享同一文件的步骤 | 两个功能分支并行开发 |
| 自动化 / heartbeat | 定时检查、提醒、监控和后续跟进 | 一次性立即任务 | 每周学习复盘 |
| Hook | 生命周期上的机械检查或阻止规则 | 开放式复杂判断 | 任务结束时运行实验室检查 |

## 选择口诀

1. 一次性的，先用提示。
2. 每次都要遵守的，放 `AGENTS.md`。
3. 重复的做法，做成 Skill。
4. 需要外部系统，用 MCP 或连接器。
5. 需要安装分发，做成插件。
6. 可独立并行，才用子智能体或 worktree。
7. 到时间重复，用自动化。
8. 必须机械执行或阻止，用 Hook。

## 可靠性检查

- **上下文**：输入是否完整，路径和版本是否明确？
- **指令**：目标、范围、限制、输出、验收是否矛盾？
- **工具**：工具是否真的可用，调用是否产生副作用？
- **数据**：资料是否缺失、过期、编码错误或未经授权？
- **验证**：是否只是“没报错”，还是检查了真实结果？
